02

The pipeline, start to finish

A scheduled job wakes every hour and fetches the register whenever the last snapshot is at least three and a half hours old, so the data refreshes about every four hours. It commits the raw answer to the repository. The bar at the top of every page counts down to the next refresh. The forecast is then rebuilt from the full archive and published as one file, which this site reads. If any step fails, the previous forecast stays up.

04

What the model actually looks at

Only what is in the public record. Every input is divided by the series’ own recent level, so a three-unit whole-blood group and a two-thousand-unit red-cell group can share one model. There are no weather, calendar or demand inputs yet.

Reproducible by design

Same inputs, same forecast, every time.

Every forecast file is stamped with the snapshot it was built from, the model is seeded, and every raw snapshot is kept in the repository. Any forecast on this site can be regenerated from the record it was built on.
